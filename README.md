# 🧮 Mini NPU Simulator

MAC(Multiply-Accumulate, 곱하고 누적해서 더하기) 연산으로 입력 패턴이 **십자가(Cross)** 인지 **X** 인지 판정하는 Python 콘솔 프로그램입니다.
NumPy 같은 외부 라이브러리 없이 반복문으로 직접 구현했습니다.

## 1. 실행 방법
```bash
python main.py          # macOS/Linux 는 python3 main.py
```
- 요구 사항: Python 3.8 이상, 표준 라이브러리만 사용 (`json`, `time`, `os`, `re`)
- `data.json` 은 `main.py` 와 **같은 폴더**에 둡니다.
- 실행하면 모드를 고릅니다.

| 입력 | 모드 | 흐름 |
|---|---|---|
| `1` | 사용자 입력 (3×3) | 필터 A, B 입력 → 저장 확인 → 패턴 입력 → MAC 연산 → 판정 → 성능 분석(3×3) |
| `2` | data.json 분석 | 필터 로드 → 패턴 로드/검증 → MAC·판정·PASS/FAIL → 성능 분석(3/5/13/25) → 결과 요약 |
| `3` | (보너스) | 2차원 vs 1차원 배열 MAC 성능 비교, N×N Cross/X 패턴 생성기 |

입력 예시 (모드 1, 한 줄에 숫자 3개를 공백으로 구분)
```
0 1 0
1 1 1
0 1 0
```
행의 숫자 개수가 3개가 아니거나 숫자가 아닌 값이 있으면 `입력 형식 오류: ...` 안내 후 해당 행렬을 처음부터 다시 입력받습니다.
`Ctrl+C` / 입력 종료(EOF) 시에는 안내 후 정상 종료합니다.

## 2. 구현 요약

### 2-1. 데이터 구조
- `Matrix` 클래스: n×n 2차원 리스트 보관, `get(r, c)` / `set(r, c, v)` 로 특정 위치 읽기·쓰기, `is_square()` 로 정사각 여부 검사
- 3×3, 5×5, 13×13, 25×25 (그 이상도) 처리 가능

### 2-2. 라벨 정규화 (표준 라벨: `Cross`, `X`)
data.json 안에서 같은 뜻의 라벨이 서로 다르게 적혀 있습니다.

| 위치 | 원래 값 | 표준 라벨 |
|---|---|---|
| `patterns.*.expected` | `"+"` | `Cross` |
| `patterns.*.expected` | `"x"` | `X` |
| `filters.size_N` 키 | `"cross"` | `Cross` |
| `filters.size_N` 키 | `"x"` | `X` |

`normalize_label()` 이 앞뒤 공백 제거 + 소문자 변환 후 `LABEL_MAP` 표에서 찾아 표준 라벨로 바꿉니다.
콘솔 출력과 PASS/FAIL 비교는 **모두 표준 라벨 기준**입니다. 정규화하지 않으면 `"+" != "Cross"` 처럼 문자열이 달라 정답인데도 FAIL 이 됩니다.

### 2-3. 키 해석 및 스키마 검증
- 패턴 키 `size_{N}_{idx}` 에서 정규식 `^size_(\d+)` 로 N 을 꺼내 `size_N` 필터를 선택
- 다음 경우는 **해당 케이스만 FAIL** 로 기록하고 프로그램은 계속 진행 (비정상 종료 없음)
  - 키에서 N 추출 실패, `input` 누락, expected 라벨 해석 불가
  - `size_N` 필터 없음, 패턴 크기 ≠ 필터 크기 (예: `필터 13×13, 패턴 5×5`)
  - 그 밖의 예상 못 한 예외 (`try/except` 로 케이스 단위 처리)

### 2-4. MAC 연산
```python
def mac(pattern, flt):
    total = 0.0
    for r in range(n):
        for c in range(n):
            total += pattern[r][c] * flt[r][c]   # 같은 위치끼리 곱하고 누적
    return total
```

### 2-5. 동점 처리 정책 (epsilon)
```python
EPSILON = 1e-9
if abs(score_cross - score_x) < EPSILON: 판정 = UNDECIDED
```
부동소수점(소수를 2진수로 근사 저장하는 방식)은 `0.1 * 9` 를 정확히 `0.9` 로 만들지 못하고 `0.8999999999999999` 가 됩니다.
그래서 `==` 대신 **차이가 아주 작으면 같은 값으로 보는** 허용오차 비교를 사용합니다.

### 2-6. 성능 측정
- `time.perf_counter()` 로 **MAC 함수 호출 구간만** 10회 반복 측정 후 평균(ms)
- 입력·출력·파일 읽기 시간은 측정에서 제외
- 측정용 패턴은 패턴 생성기(`make_cross(n)`)로 만든 N×N 십자가

## 4. 결과 리포트

### 4-1. 실패 원인 분석
1. 실패 3건(`size_5_1`, `size_13_2`, `size_25_1`)은 모두 **로직 문제나 스키마 문제가 아니라 "수치 비교 문제"** 입니다. 라벨 정규화 후 expected 는 모두 정상 해석되었고, 필터·패턴 크기도 모두 일치했습니다.
2. 세 케이스는 data.json 의 필터 값이 **두 필터 점수가 수학적으로 정확히 같아지도록** 설계되어 있습니다.
3. `size_5_1`(X 패턴): Cross 필터는 중앙값 `0.9` 하나만 겹쳐 0.9, X 필터는 `0.1 × 9칸` = 0.9 → 수학적으로 동점. 하지만 부동소수점 누적 합은 `0.8999999999999999` 가 됩니다.
4. `size_13_2`(Cross 패턴): Cross 필터는 `0.3 × 25칸` = 7.5(실제 합 `7.499999999999997`), X 필터는 중앙값 `7.5` 하나 → 동점.
5. `size_25_1`(X 패턴): Cross 필터 중앙값 `4.9`, X 필터 `0.1 × 49칸` = 4.9(실제 합 `4.899999999999999`) → 동점.
6. epsilon 없이 `>` 로 단순 비교했다면 오차 방향에 따라 `size_5_1`→Cross, `size_13_2`→X, `size_25_1`→Cross 로 **오히려 틀린 라벨**을 확신하고 출력했을 것입니다. 즉 오차 10⁻¹⁵ 수준의 우연이 판정을 뒤집습니다.
7. `abs(a-b) < 1e-9` 정책을 적용하면 세 케이스는 일관되게 `UNDECIDED`(판정 불가)가 되고, 과제 규칙(동점은 판정 불가 → expected 와 다르므로 FAIL)에 따라 FAIL 로 집계됩니다. 이는 **잘못된 확신 대신 "판정 불가"를 정직하게 보고한 결과**입니다.
8. 진단 순서는 ① 데이터/스키마(라벨·키·크기) → ② 로직(MAC 계산 손검증) → ③ 수치 비교(점수 차이가 1e-9 미만인지) 로 나누어 확인했고, ①②는 이상 없음, ③에서 원인을 확인했습니다.
9. 반대로 PASS 3건은 점수 차이가 충분히 커서(예: 8.9 vs 0.1) epsilon 과 관계없이 판정이 명확했습니다.
10. 라벨 정규화를 하지 않았다면 expected `"+"`/`"x"` 와 판정 `Cross`/`X` 가 문자열로 달라 **PASS 3건까지 전부 FAIL** 이 되었을 것입니다. 정규화가 "데이터 표기 차이"로 인한 실패를 0건으로 만들었습니다.

### 4-2. 시간 복잡도 분석
1. MAC 연산은 N×N 칸을 한 번씩 방문해 곱셈 1번 + 덧셈 1번을 하므로 연산 횟수는 **N²** 이고, 시간 복잡도는 **O(N²)** 입니다.
2. 크기가 3→25 로 약 8.3배 커지면 연산 횟수는 9→625 로 약 **69배**(8.3²) 늘어납니다.
3. 실측도 같은 경향입니다: 13×13(169회) 0.0041 ms → 25×25(625회) 0.0139 ms. 연산 횟수 비 3.7배, 시간 비 약 3.4배로 거의 비례합니다.
4. 3×3, 5×5 처럼 아주 작은 크기에서는 함수 호출·반복문 준비 같은 **고정 비용**이 커서 N² 비례가 덜 뚜렷합니다 (0.0006 vs 0.0009 ms).
5. 따라서 N 이 커질수록 "시간 ≈ 상수 × N²" 에 가까워집니다. 예를 들어 100×100 이면 25×25 대비 16배 정도의 시간이 예상됩니다.
6. 실제 AI 모델은 이런 필터를 수천 개, 이미지 위치마다 반복 적용하므로 연산량이 수억 번으로 커지고, 그래서 MAC 을 병렬로 처리하는 NPU 가 필요합니다.
